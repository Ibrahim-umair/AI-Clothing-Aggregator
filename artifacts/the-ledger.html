variant_snapshots and scrape_runs aren't shown populated here — they're append-only history tables, and inventing fake multi-day history would break the "every value is real" rule this whole project has run on. They'll start filling for real the moment the daily scrape job runs against this schema.

Notice what the color-coding makes visible for free: the unstitched suit (teal) is the only row anywhere with a real product_pieces entry — and its one variant has no size at all, because unstitched fabric isn't sized the way a garment is. The perfume (purple) is the only row with size_system = volume_ml and a null color. Nothing was forced to look uniform across categories, which was the whole point.
